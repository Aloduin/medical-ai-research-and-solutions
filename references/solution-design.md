# 方案设计

## 选定探索尺度

- 合作意向或建设方向还宽泛时，按现有流程、数据资产、目标用户和可售服务产生几个有实质差异的方向。以当前信息说明哪个方向值得优先核查。
- 场景已明确但方案待定时，比较人工作流、规则或轻量方法、可复用产品及联合研发。评估组合能力带来的实际收益和交付成本。
- 科研问题已明确时，集中比较临床机制、数据质量、基线、分析与验证策略。用合适的设计回应关键不确定性。

## 候选方向的最小论证

| 问题 | 需要交代 |
| --- | --- |
| 谁需要 | 使用者、真实工作步骤、痛点、服务提供者和决策者 |
| 为什么做 | 可观察的改善及代价，AI 相对现行流程或简单方法的增量 |
| 依据何在 | 已有证据的范围、项目侧验证与待验假设 |
| 能否开始 | 关键数据的存在、访问权限、样例质量和时间覆盖，接口、团队、预算与审批条件 |
| 如何交付 | 临床研究报告、数据或模型验证、工作台、服务模块或系统 |
| 怎样验证 | 评估单元、可比基线、测量指标、验收证据、可继续和需缩小的条件 |

对触及硬约束的方向，注明阻断的环节和可核查的解法。对可继续的方向，用可说明来源的定性判断比较价值、成熟度、可获得性、资源与风险。缺少数据支持时给出条件性推荐、备选和重排条件。使用定量评分时说明量表、权重和敏感性。

## 组织交付

| 用途 | 首期交付需要有 | 后续推进条件 |
| --- | --- | --- |
| 临床科研与联合研发 | 研究问题、纳排与数据、分析单位、对照、偏差控制、验证和伦理安排 | 数据及标签通过审计，方法达到预先约定的质量或性能标准，局限能由临床团队复核 |
| 医院智慧化建设 | 现状流程、优先场景、输入输出、人机分工、设备/系统接口、接入核查与试点 | 数据可持续接入，有明确责任人及异常处理，按流程定义试点验收及上线条件 |
| 医疗企业 AI 合作 | 交付形态、使用者与采购者、服务流程、运行团队、成本和付费假设 | 试点客户可确认，工作量和采用效果可测，交付成本和付费意愿能验证 |

在方案中标明已核验能力、正在验证功能、首期规划和后续愿景的证据范围。说明首期的对象、范围、角色、分期、关键依赖、样例及验收。阈值、预算、规模或排期缺少依据时，给出定标方式或带条件的估算。区分流程效率、技术性能与临床获益，分别明确验证路径。
